The Loop in Four Lines

Training is one loop, repeated: take a batch of text, run the model forward, score its guesses with a loss, send the gradient of that loss backward through every weight, and nudge each weight downhill (update). One turn is one training step.

src/lib/training/trainer.ts (transformer-explainer)
export function trainStep(tr: Trainer, batch?: Batch): StepLog {
  const { cfg } = tr;
  const b =
    batch ?? sampleBatch(tr.train, cfg.batch, cfg.model.seq_len, tr.rng);
  const { loss, grads } = lossAndGrads(
    tr.params,
    cfg.model,
    b.inputs,
    b.targets,
  );
  const { norm, scale } =
    cfg.clip === null
      ? { norm: NaN, scale: 1 }
      : clipByGlobalNorm(grads, cfg.clip);
  const lr = lrAt(tr.t, { ...cfg.schedule, total: cfg.steps });
  optimizerStep(tr.opt, tr.params, grads, lr);
  const log = { step: tr.t, lr, loss, gradNorm: norm, clipScale: scale };
  tr.t += 1;
  return log;
}

In PyTorch the same four steps are loss = model(x, y), loss.backward(), clip_grad_norm_(…) and opt.step(). They are the heart of every training loop, from this toy to a model trained on thousands of accelerators; decks 03 and 04 open up the backward pass and the optimiser.

02

The Model and the Text It Trains On

The model is Part 1’s decoder, with the same random initial weights: the one Part 1 of the site runs for inference. Part 2 trains it.

The model (results.md §2)

  • context 8 characters, width 16, 2 heads, FFN 32, 2 blocks
  • vocabulary 64 characters, initial weights from seed 42
  • 5,376 parameters

The corpus (results.md §1)

  • Alice’s Adventures in Wonderland (Project Gutenberg eBook #11, public domain)
  • 142,041 characters: training 127,837, validation 14,204 (the last 10%)
  • each step: 16 windows of 8 characters = 128 predictions

The default run: AdamW (β1 0.9, β2 0.99, weight decay 0.01), learning rate 0.01 with 50 warmup steps then a cosine to a tenth of it, gradient clipping at norm 1, 2,000 steps. It took 8.3 s in NumPy on a CPU. Small enough to follow every number; large enough to show the real phenomena.

03

Next-Token Prediction: One Window, Eight Predictions

A training example is a window of 9 consecutive characters. The first 8 are the input; the target at each position is the character after it. Feed “alice wa” in and the model returns 8 rows of 64 logits, one per position. Thanks to the causal mask, row \(i\) saw only characters \(1 \dots i\), so each row is a genuine prediction of character \(i+1\).

The model always predicts from the true text so far, never from its own guesses: teacher forcing. So all 8 positions are scored at once, in one forward pass. This is what makes transformers efficient to train, compared with generating, where each token must wait for the one before. The chain rule of probability makes it exact:

$$\begin{aligned}&\log p_\theta(w_2,\dots,w_{9} \mid w_1) \\ &\quad= \sum_{i=1}^{8} \log p_\theta(w_{i+1} \mid w_{1..i})\end{aligned}$$
04

Cross-Entropy, and Why Minus the Log

The loss is the mean, over every predicted position, of minus the log of the probability the model gave the character that actually came next: the next-token cross-entropy.

$$L(\theta) = -\frac{1}{BS}\sum_{b=1}^{B}\sum_{i=1}^{S} \log p_\theta\big(y_{b,i} \mid x_{b,1..i}\big)$$

Probability 1 costs nothing; 1/2 costs ln 2 ≈ 0.69; 1/64 costs ln 64 = 4.1589, the score of a uniform guess. Being confidently wrong is expensive without limit, so the model keeps some probability on everything plausible. Averaged over the text, the loss is the number of nats needed to encode each next character, and minimising it is maximum-likelihood estimation.

05

The Gradient of the Loss Is p − y

With logits \(z\) and \(p = \operatorname{softmax}(z)\), the loss at one position and its gradient are

$$\begin{gathered}\ell = -\log p_y = -z_y + \log \sum_j e^{z_j} \\ \frac{\partial \ell}{\partial z_k} = p_k - \mathbf 1[k = y]\end{gathered}$$

What it says

The right character’s logit is pushed up by \(1 - p_y\); every other logit is pushed down by its own probability. The pushes sum to zero. When the model is already right, the gradient vanishes; when it is confidently wrong, it is large.

How it is computed

\(\log\sum_j e^{z_j}\) is evaluated as \(m + \log\sum_j e^{z_j - m}\) with \(m = \max_j z_j\), so no exponential overflows. For the mean over \(N = BS\) positions each row is divided by \(N\). Everything in backpropagation (deck 03) starts from this vector.

src/lib/training/loss.ts: the whole backward pass of the loss
return probs.map((p, i) =>
  p.map((v, j) => (v - (j === targets[i] ? 1 : 0)) / n),
);

Label smoothing replaces the one-hot target with \((1-\varepsilon)\mathbf 1_y + \varepsilon/V\) (Szegedy et al. 2015, §7); it is common in translation and image classification, while language-model pretraining usually uses the plain loss, as here.

06

A Real Loss Curve, Plateau Included

The default run: AdamW, 2,000 steps of 16 windows of 8 characters (results.md §4). Training loss every 10 steps; validation loss every 100.

At step 0 every character is about equally likely: validation loss 4.1774, against ln 64 = 4.1589. By step 200 it is 2.9446, close to 3.0000, the unigram entropy of the text: what a model scores if it knows only how common each letter is. Then it sits there for several hundred steps. A model this small, started this small, first learns letter frequencies through its output layer, and only later finds that the previous characters (which attention must route to the current position) tell it far more. Once it does, the loss falls again: 2.7777 at step 1,000 and 2.2993 at step 2,000.

07

Training Loss, Validation Loss and Perplexity

Two losses

The training loss is measured on each step’s own batch: noisy, because every batch differs. The validation loss scores a fixed set of windows from the held-out end of the book, text the model never trains on. If training loss kept falling while validation loss rose, the model would be memorising (overfitting). Here they stay together: the run sees each training character about 2.0 times, far too little for 5,376 weights to memorise 127,837 characters.

Perplexity

\(e^{L}\) turns a loss back into a count: a model with loss \(L\) is as unsure as a uniform choice among \(e^{L}\) tokens. The run ends at a validation perplexity of 10.0, against 20.1 for letter frequencies alone and 64 for a uniform guess. Perplexities compare only with the same tokeniser: a BPE token covers more text than a character.

08

Seeds and Spread

Everything random is seeded: the weights (seed 42, Part 1’s), the order of the batches (data seed 1) and the sampler (seed 7). The same seeds give the same run on any machine, which is why the site’s browser run lands on the recorded one.

A different data seed gives a different curve. The default settings over data seeds 1, 2 and 3 end at 2.299, 2.354 and 2.178: mean ± standard deviation 2.277 ± 0.090 (results.md §6a).

The rule every later deck follows

A difference smaller than the seed-to-seed spread is not a difference, and a result from a single seed is a hypothesis until it is repeated. Many of these runs are also chaotic: when the model leaves the plateau depends on the last bits of its arithmetic, so recomputing a run on another CPU moved single seeds’ final losses by up to about 0.35 (results.md, “how to read these numbers”). Every comparison in this series is three seeds, mean ± standard deviation.

11

What to Take Away

  • One step = batch → forward → loss → backward → update; everything else in this series is a refinement of one of those five.
  • Teacher forcing scores every position of a window at once; the causal mask keeps it honest.
  • Cross-entropy is minus the log probability of the truth; its gradient at the logits is \(p - y\).
  • Loss curves have plateaus: this one sits at the letter-frequency loss (3.00) for hundreds of steps before attention starts to pay.
  • Compare runs on validation loss, over several seeds.
